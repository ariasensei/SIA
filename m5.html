Now we move into one of the most important areas of modern game development: Networking and Online Systems.

Modern games can allow players to play with other people, join online matches, communicate with teammates, save progress online, view leaderboards, purchase digital items, download updates, connect to game servers, and synchronize game states. All of these require some form of network communication.

III–V · Foundations

What is networking?

Simple Definition

Networking is the process of allowing computers and software systems to communicate and exchange information. In game development, game networking allows different game clients and online systems to exchange game-related information.

Player-to-player communication

Player A
   ↓
Internet
   ↓
Game Server
   ↓
Internet
   ↓
Player B

Player A's computer and Player B's computer do not usually communicate completely independently. A server may coordinate the game.

VII–XVI · Multiplayer Architecture

Why does a game need networking?

Consider an online FPS. Player A shoots Player B. The game needs to communicate Player A position, rotation, weapon used, shot fired, shot direction, and time of shot. The server may then determine: Was Player A allowed to shoot? Did the weapon have ammunition? Did the shot hit Player B? How much damage should be applied?

IX. Client

A client is the software running on the player's device that communicates with an online service. Examples include PC, mobile, and console games. The client usually handles graphics, input, local UI, audio, some game logic, sending player actions, and receiving game-state information.

X. Server

A server provides services to clients. A game server may manage players, game rules, match state, player positions, scores, health, inventory, and match results.

XI–XIII. Client-Server Architecture and Dedicated Servers

Centralized game coordination

            GAME SERVER
          /      |      \
      Client   Client   Client
       A         B        C

        DEDICATED SERVER
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
   Player A Player B Player C

Client-server architecture uses a central server to coordinate the game. Advantages include centralized game state, easier management, better control over game rules, easier player management, server-side validation, and better protection against some forms of cheating. However, servers cost money and must be maintained.

XV. Peer-to-Peer

Peer-to-peer networking allows participants to communicate directly rather than relying entirely on a dedicated central game server.

Player A ←→ Player B
   ↕           ↕
Player C ←→ Player D

P2P Advantages

  • Can reduce dedicated-server requirements.
  • Can be useful for certain applications.

P2P Disadvantages

  • More difficult security considerations.
  • Host migration problems.
  • One player's connection may affect others.
  • Greater exposure to cheating or manipulation depending on design.

XVI. Client-Server vs. P2P

XVII–XXXII · Data Transmission

IP address, ports, packets, protocols, TCP, and UDP

XVII. IP Address

An IP address identifies a device or network interface using the Internet Protocol. Example: 192.168.1.20, a private IPv4 address. A networked system needs an address so other systems know where to send data.

XVIII. Port

An IP address identifies the destination device or interface. A port identifies the application or service on that device. Think of it as: IP Address = Building Address; Port = Room Number. Example: 192.168.1.20 : 7777.

XIX–XX. Packets and Protocols

Network data is typically divided into small pieces called packets. A protocol is a set of rules for communication: how data is formatted, sent, received, and how errors are handled. Examples include TCP, UDP, HTTP, and WebSocket.

Game Data
   ↓
Packets
   ↓
Network
   ↓
Packets
   ↓
Game

XXI. TCP

TCP means Transmission Control Protocol. It is designed for reliable, ordered communication. It is connection-oriented, supports reliable delivery, ordered data, error checking, and retransmission of lost data. TCP is useful when correctness matters more than extremely low latency.

XXII. UDP

UDP means User Datagram Protocol. It is lightweight and does not provide the same built-in reliability and ordering guarantees as TCP. It can be useful when speed and timely updates are more important than receiving every packet. Some multiplayer systems use UDP-based communication or protocols built around UDP.

XXIII. TCP vs UDP

Feature TCP UDP
Connection-oriented Yes No
Reliability Built-in Not built-in
Ordering Yes Not guaranteed
Retransmission Yes Not built-in
Overhead Higher Lower
Typical use Reliable data transfer Real-time applications
Game networking Some uses Common in real-time networking

Important: Do not simply think “UDP is always better for games.” The correct choice depends on the system's requirements.

XXIV–XXV. Examples

A chat message such as “Hello team!” should arrive correctly, so reliability is important. For player positions such as X=100, 101, 102, 103, and 104, an old lost update can become unnecessary when a newer update arrives. This is one reason UDP-based networking is common in real-time games.

XXVI–XXXII. Latency, Ping, Bandwidth, Packet Loss, and Jitter

Latency is delay between sending information and receiving a response. Ping is commonly used to describe round-trip time, such as 30 ms. Bandwidth is the amount of data that can be transmitted through a connection over time—the width of the network pipe. Packet loss occurs when packets fail to reach their destination. Jitter is variation in packet arrival time.

Packet 1 → 20 ms
Packet 2 → 22 ms
Packet 3 → 80 ms
Packet 4 → 25 ms

The four major network problems: 1. High Latency — data takes too long. 2. Packet Loss — some data does not arrive. 3. Jitter — data arrives inconsistently. 4. Limited Bandwidth — too much data is being transmitted for the available capacity.

XXXIII–XLVI · Game State and Synchronization

Keeping multiplayer games consistent and responsive

Game State and Synchronization

The game state is the current condition of the game: player positions, health, scores, inventory, and other relevant values. Synchronization means keeping different systems consistent with each other.

SERVER
Player Position = 100
       ↓
CLIENT A: Position = 100
       ↓
CLIENT B: Position = 100

Server Authority and Validation

Server authority means the server determines the official game state. If a client says, “I shot the enemy,” the server verifies the action, calculates the result, and distributes the official update. This is safer than blindly trusting clients that may claim unrealistic health, money, weapon damage, or movement values.

CLIENT
"I want to shoot."
      ↓
SERVER
"Is that action valid?"
      ↓
SERVER
"Yes."
      ↓
CLIENTS
"Display the result."

Client-Side Prediction and Reconciliation

Client-side prediction lets a client immediately predict an action instead of waiting for server confirmation. This makes controls feel responsive. If the client predicts position 100 but the server says 95, the client corrects itself using reconciliation.

Interpolation and Extrapolation

Interpolation smoothly transitions between known states, such as displaying 100, 102, 104, 106, 108, and 110 instead of jumping directly from 100 to 110. Extrapolation estimates a likely future state based on movement, but may be incorrect when direction changes.

Server Tick and Tick Rate

A server tick is one update cycle. A server running at 60 ticks per second updates approximately 60 times per second. Higher tick rates provide more frequent updates but may need more CPU, network processing, and bandwidth. Higher is not automatically better.

Replication and Interest Management

Replication shares relevant state information between systems. Interest management, also called relevancy filtering, sends players only information relevant to them—such as nearby players—rather than every update from all 999 other players in a large multiplayer game. This reduces bandwidth, processing, and unnecessary data.

XLVII–LXV · Online Systems

Matchmaking, identity, backend services, and scalability

Matchmaking and Lobby

Matchmaking finds suitable players and places them into a game session. It may consider region, ping, skill, game mode, party size, and availability. A lobby is an area where players gather before entering a game, inviting friends and becoming ready.

Player searches for match
          ↓
   Matchmaking Service
          ↓
Find suitable players
          ↓
Create / assign match
          ↓
Game Server
          ↓
Players connect

Authentication and Authorization

Authentication answers “Who are you?” Authorization answers “What are you allowed to do?” An authenticated player may access their own profile, inventory, and saves, but should not access another player's private data.

Database and Backend

Online games may store player accounts, profiles, inventory, achievements, statistics, progress, and purchases in a database. The client should not directly access the database. A safer architecture is Game Client → Game Server → Backend Service → Database. The backend is the server-side portion of an application and performs many server-side operations.

Persistent Data, Session, and Heartbeat

Persistent data remains after the game closes: level progress, inventory, achievements, profiles, and account information. A session is the time a player is connected. A heartbeat is a small periodic message showing that a connection is still active. If heartbeats stop, the server may detect a disconnect.

Disconnection and Reconnection

Connection Lost
      ↓
Attempt Reconnect
      ↓
Success?
 ↓          ↓
YES        NO
 ↓          ↓
Resume    Return to Menu

Online games must handle Internet loss, crashes, closing the game, timeouts, and network changes without simply crashing. Reconnection may follow CONNECTED → DISCONNECTED → RECONNECTING → CONNECTED.

Scalability, Load Balancing, and Regional Servers

Scalability is the ability to handle growing workloads: 100 players, 10,000 players, or 1,000,000 players. Load balancing distributes traffic across multiple servers. Regional servers allow players to use nearby infrastructure, such as Philippines and Japan connecting to Asia servers, reducing latency compared with distant routes.

             Load Balancer
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
   Server A   Server B   Server C
LXVI–LXX · Security and Architecture

Security, cheating, validation, and DDoS

Online systems must consider account security, authentication, authorization, data validation, encryption, cheating, abuse, DDoS attacks, and API security.

Cheating and Server-Side Validation

A cheater may try to manipulate position, health, money, inventory, weapon damage, or movement speed. A key defense is: Do not trust the client with critical game decisions.

Player says:
"I purchased an item for 100 coins."
       ↓
Server checks:
Does player have 100 coins?
       ↓
YES → Complete transaction
NO  → Reject transaction

DDoS

DDoS means Distributed Denial-of-Service. It overwhelms a service with high traffic or requests, making access difficult for legitimate users. Game servers can be targets, so developers and infrastructure providers need appropriate network and security protections.

LXXXV–LXXXVI · Mini Case Study

Online FPS

Imagine developing a competitive FPS. Player A shoots Player B.

  1. Input: Player presses the mouse button. Input → Client.
  2. Network: The client sends an action to the server.
  3. Validation: Server checks whether the player is alive, weapon exists, ammunition is available, the shot is possible, and the target is valid.
  4. Result: Server calculates Hit = TRUE and Damage = 40.
  5. State update: Player B Health changes from 100 → 60.
  6. Replication: Result is replicated to relevant clients.

Important concept: “The client shows; the server decides.” The client is responsible for the player's experience. The server should make important authoritative decisions. Actual game architectures vary, but this is a useful conceptual model.

XC–XCI · Key Takeaways

Ten concepts to remember

  1. Client: The player's game application.
  2. Server: Provides services and may manage authoritative game state.
  3. Packet: A unit of network data.
  4. Protocol: Rules used for communication.
  5. Latency: Communication delay.
  6. Packet Loss: Data that does not successfully arrive.
  7. Synchronization: Keeping relevant game states consistent.
  8. Server Authority: Server determines official state.
  9. Prediction: Client estimates what will happen to reduce perceived delay.
  10. Scalability: Ability to support increasing players and workloads.
